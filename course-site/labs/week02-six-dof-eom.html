1 · The 5-minute recap

The quadrotor is a rigid body with a 12-state vector. Translation lives in the world frame, rotation in the body frame. The conventions are locked course-wide: z-up / ENU (gravity \(-z\), thrust along \(+\)body-\(z\)), ZYX intrinsic Euler, \(R\) maps body→world.

The four blocks you re-implement — and the exact lines they map to in dynamics.py:

\[ \dot{\mathbf p}=\mathbf v,\quad \dot{\mathbf v}=\begin{bmatrix}0\\0\\-g\end{bmatrix}+\frac{1}{m}R\begin{bmatrix}0\\0\\T\end{bmatrix},\quad \dot{\boldsymbol\eta}=W(\phi,\theta)\,\boldsymbol\omega,\quad \mathbf I\dot{\boldsymbol\omega}=\boldsymbol\tau-\boldsymbol\omega\times\mathbf I\boldsymbol\omega \]

with the Euler-rate matrix \( W=\begin{bmatrix}1 & \sin\phi\tan\theta & \cos\phi\tan\theta\\ 0 & \cos\phi & -\sin\phi\\ 0 & \sin\phi/\cos\theta & \cos\phi/\cos\theta\end{bmatrix} \). State layout: x[0:3] position, x[3:6] velocity, x[6:9] Euler \((\phi,\theta,\psi)\), x[9:12] body rates \((p,q,r)\); input u = [T, τx, τy, τz].

Two convention traps to avoid
  • NED sign flip. If you copy the acceleration line from a NED source (Beard & McLain), gravity is \(+z\) there. We are z-up: gravity is \([0,0,-g]\) and thrust is \(+\)body-\(z\). Mixing them is the classic bug.
  • Don't drop the gyroscopic term. \( -\boldsymbol\omega\times\mathbf I\boldsymbol\omega \) is small near hover but nonzero — leaving it out is exactly what pushes your error above \(10^{-9}\).

3 · Build the model

Create examples/wk2_eom.py and fill in my_state_derivative(x, u, p) block by block. Each step adds a few lines.

1 Unpack the state & input edit my_state_derivative()

Pull the slices and the wrench apart, exactly as the reference does:

phi, theta, psi = x[6], x[7], x[8]
omega = x[9:12]                 # body rates (p, q, r)
T, tau = u[0], u[1:4]           # thrust [N], body torques [N·m]
2 Translational block world frame · z-up

Position integrates velocity. Acceleration is gravity (\(-z\)) plus body-\(z\) thrust rotated to world by \(R\):

R = rotation_matrix(phi, theta, psi)
accel = np.array([0.0, 0.0, -p.g]) + (R @ np.array([0.0, 0.0, T])) / p.mass

Sign check: thrust is +body-z and gravity is −g. If you wrote +p.g you copied a NED source — flip it.

3 Rotational kinematics W · ω

Body rates are not Euler-angle rates — convert with \(W=\)euler_rate_matrix:

euler_dot = euler_rate_matrix(phi, theta) @ omega
4 Rotational dynamics Euler's equation · keep ω×Iω

Euler's equation in the body frame. Keep the gyroscopic cross-product term:

omega_dot = p.I_inv @ (tau - np.cross(omega, p.I @ omega))
5 Assemble \( \dot{\mathbf x} \) return the 12-vector

Stack the four blocks back into one length-12 derivative in the same order as the state:

dx = np.empty(12)
dx[0:3]  = x[3:6]       # p_dot = v
dx[3:6]  = accel
dx[6:9]  = euler_dot
dx[9:12] = omega_dot
return dx

def my_state_derivative(x, u, p):
    phi, theta, psi = x[6], x[7], x[8]
    omega = x[9:12]
    T, tau = u[0], u[1:4]

    R = rotation_matrix(phi, theta, psi)
    accel = np.array([0.0, 0.0, -p.g]) + (R @ np.array([0.0, 0.0, T])) / p.mass

    euler_dot = euler_rate_matrix(phi, theta) @ omega
    omega_dot = p.I_inv @ (tau - np.cross(omega, p.I @ omega))

    dx = np.empty(12)
    dx[0:3]  = x[3:6]
    dx[3:6]  = accel
    dx[6:9]  = euler_dot
    dx[9:12] = omega_dot
    return dx

4 · Run & verify

Save this as examples/wk2_eom.py. It wraps your block in a small driver, then checks it against the reference on many random states and inputs — the exact checkpoint for this lab:

# examples/wk2_eom.py — Week 2 checkpoint: match the reference 6-DOF model
import numpy as np
from quadsim import QuadParams
from quadsim.dynamics import (
    rotation_matrix, euler_rate_matrix, state_derivative,
)

p = QuadParams()


def my_state_derivative(x, u, p):
    phi, theta, psi = x[6], x[7], x[8]
    omega = x[9:12]
    T, tau = u[0], u[1:4]

    R = rotation_matrix(phi, theta, psi)
    accel = np.array([0.0, 0.0, -p.g]) + (R @ np.array([0.0, 0.0, T])) / p.mass

    euler_dot = euler_rate_matrix(phi, theta) @ omega
    omega_dot = p.I_inv @ (tau - np.cross(omega, p.I @ omega))

    dx = np.empty(12)
    dx[0:3]  = x[3:6]
    dx[3:6]  = accel
    dx[6:9]  = euler_dot
    dx[9:12] = omega_dot
    return dx


# --- verify on random states/inputs (keep pitch away from gimbal lock) ---
rng = np.random.default_rng(0)
max_err = 0.0
for _ in range(10_000):
    x = rng.uniform(-2.0, 2.0, size=12)
    x[7] = rng.uniform(-1.2, 1.2)            # pitch in (-69, 69) deg: avoid 1/cos(theta) blow-up
    u = np.concatenate([[rng.uniform(0, 10)], rng.uniform(-0.5, 0.5, size=3)])
    err = np.max(np.abs(my_state_derivative(x, u, p) - state_derivative(x, u, p)))
    max_err = max(max_err, err)

print(f"max abs error vs reference = {max_err:.3e}")
assert max_err < 1e-9, "model does not match the reference"
print("PASS — your 6-DOF model matches quadsim to machine precision")
export PYTHONPATH=.
python examples/wk2_eom.py
Expected — your graded checkpoint ⭐
  • max abs error \(\approx 10^{-16}\)–\(10^{-15}\) (machine precision) — and certainly \(< 10^{-9}\).
  • The script prints PASS and the assert does not fire.
  • You record the printed error number — it is part of the deliverable.

If the error is large, the usual culprits: a sign flip on gravity/thrust (NED vs z-up), a dropped \(\boldsymbol\omega\times\mathbf I\boldsymbol\omega\) term, or using omega directly as euler_dot instead of \(W\boldsymbol\omega\). Walk the four blocks against the slides.

Self-check

5 · Going further (optional)

  • Break it on purpose. Flip gravity to +p.g and re-run. How big is the error, and at which state slice does it show up?
  • Hover trim. Feed a level, at-rest state with u = [p.weight, 0, 0, 0] and confirm \(\dot{\mathbf x}\approx0\) — hover is a fixed point of \(f\).
  • Gimbal lock. Set pitch x[7] = np.deg2rad(89.9) and watch \(W\) (and so euler_dot) explode — the ZYX singularity, and the reason Week 1 introduced quaternions.
