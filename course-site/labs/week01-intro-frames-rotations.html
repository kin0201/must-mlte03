1 · The 5-minute recap

The course uses a world frame that is ENU / z-up (gravity points \(-z\), thrust acts along \(+\)body-\(z\)) and a body frame glued to the airframe. The rotation matrix \(R\) carries a body vector into the world, \( \mathbf v_W = R\,\mathbf v_B \), and the simulator uses it to resolve thrust and gravity into a world-frame acceleration:

\[ \mathbf a = \begin{bmatrix}0\\0\\-g\end{bmatrix} + \frac{1}{m}\,R\begin{bmatrix}0\\0\\T\end{bmatrix} \]

We build \(R\) (body→world) from intrinsic ZYX (yaw→pitch→roll) Euler angles — exactly what quadsim.dynamics.rotation_matrix computes:

\[ R(\phi,\theta,\psi) = R_z(\psi)\,R_y(\theta)\,R_x(\phi), \qquad R^{\top}R = I,\quad \det R = +1 \]

Two gotchas from lecture Gimbal lock for ZYX sits at pitch \(\theta=\pm90^\circ\) (the second rotation) — the motivation for quaternions, which we order scalar-first \(q=[q_0,q_1,q_2,q_3]\). Beware: SciPy's Rotation.as_quat() is scalar-last by default.

3 · Explore frames & rotations

Work through the steps. The first two run an existing example; the rest are short experiments you type into a Python shell (or a scratch file) to feel what \(R\) is.

1 Run the open-loop quad it tips over

This example applies exactly hover thrust plus a tiny 0.001 N·m roll bias and no feedback. Run it and read the final roll angle it prints:

export PYTHONPATH=.
python examples/01_open_loop.py

It prints the final roll after 3 s of open loop and saves open_loop.png. The tiny bias is never corrected, so the attitude runs away — that divergence is the whole point.

2 Read the controller — why does it diverge? no feedback

Open examples/01_open_loop.py. The control() method ignores the state x entirely:

def control(self, t, x, ref):
    return np.array([self.p.weight, 0.001, 0.0, 0.0])  # 0.001 N·m roll bias

Because the command never depends on the measured attitude, nothing pushes back when the quad starts to roll. Open loop = no feedback = no stabilisation. That is the gap the rest of the course fills.

3 Build a rotation matrix ZYX

Now handle \(R\) directly. In a Python shell (with PYTHONPATH=.):

import numpy as np
from quadsim.dynamics import rotation_matrix

R = rotation_matrix(phi=0.3, theta=-0.2, psi=1.1)   # ZYX, radians
print(R)

The columns of R are the body axes \(\mathbf x_B,\mathbf y_B,\mathbf z_B\) expressed in world coordinates. The third column is where body-\(z\) (the thrust direction) points in the world.

4 Verify the two \(SO(3)\) laws the core check

A real rotation is orthonormal with unit determinant. Check both numerically:

print(np.allclose(R.T @ R, np.eye(3)))   # True  -> orthonormal, R^-1 = R^T
print(round(np.linalg.det(R), 6))        # 1.0   -> proper rotation (no reflection)

Repeat for a few of your own angles. Both must hold for every input. If either fails you've built the wrong matrix — usually a frame or Euler-order mismatch.

5 Feel gimbal lock pitch → ±90°

The Euler-rate map \(\dot{\boldsymbol\eta}=W(\phi,\theta)\,\boldsymbol\omega\) carries body rates to Euler-angle rates. Watch it blow up as pitch approaches \(\pm90^\circ\):

from quadsim.dynamics import euler_rate_matrix

for theta in [0.0, np.deg2rad(80), np.deg2rad(89), np.deg2rad(89.99)]:
    W = euler_rate_matrix(phi=0.0, theta=theta)
    print(f"theta={np.rad2deg(theta):6.2f} deg   max|W| = {np.abs(W).max():.1f}")

The entries explode (a \(1/\cos\theta\) term) — the singularity is at the second rotation, \(\theta=\pm90^\circ\). \(R\) itself stays finite, but the angle rates are undefined there. This is exactly why we move to quaternions.

4 · Run & verify

Save this as examples/wk1_frames.py. It reproduces the open-loop divergence, saves a plot, and runs the \(SO(3)\) checks in one shot — the checkpoint for this lab:

# examples/wk1_frames.py — Week 1 checkpoint: open-loop divergence + SO(3) checks
import numpy as np

from quadsim import Simulator, QuadParams
from quadsim.controllers.base import Controller
from quadsim.dynamics import hover_state, rotation_matrix


class OpenLoopHover(Controller):
    # exactly hover thrust + a tiny torque bias, NO feedback
    def __init__(self, p):
        self.p = p
    def control(self, t, x, ref):
        return np.array([self.p.weight, 0.001, 0.0, 0.0])


sim = Simulator(QuadParams())
log = sim.run(hover_state(position=(0, 0, 2.0)), OpenLoopHover(sim.params), t_final=3.0)

roll = np.rad2deg(log.euler[:, 0])
print(f"start roll = {roll[0]:6.2f} deg")
print(f"final roll = {roll[-1]:6.1f} deg   (no feedback -> it tips over)")

# SO(3) sanity check on a handful of angles
for phi, theta, psi in [(0.0, 0.0, 0.0), (0.3, -0.2, 1.1), (-0.5, 0.4, -0.7)]:
    R = rotation_matrix(phi, theta, psi)
    ok_orth = np.allclose(R.T @ R, np.eye(3))
    print(f"R^T R = I? {ok_orth}    det R = {np.linalg.det(R):.6f}")

from quadsim.plotting import plot_states
plot_states(log, save="wk1_open_loop.png", show=False)
print("saved wk1_open_loop.png")
export PYTHONPATH=.
python examples/wk1_frames.py
Expected — your graded checkpoint ⭐
  • Final roll is large (tens of degrees and growing) — the attitude diverges with no feedback.
  • Every angle triple prints R^T R = I? True and det R = 1.000000.
  • The saved wk1_open_loop.png shows roll running away from zero (it does not settle).

Self-check

5 · Going further (optional)

  • Frame check. With the quad level (\(\phi=\theta=0\)), confirm the third column of \(R\) is \([0,0,1]\) — thrust points straight up, so it exactly cancels gravity.
  • Order matters. Compare R_z R_y R_x against the reversed product R_x R_y R_z for the same angles; they differ — rotations don't commute.
  • Quaternion order trap. If you have SciPy, build a rotation with Rotation.from_euler('ZYX', ...) and print .as_quat(). Note the scalar part is last — the opposite of our scalar-first convention.
